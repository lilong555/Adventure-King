本页记录关卡完成系统：包含清理条件、传送门激活以及胜利触发流程。关卡推进系统会跨普通生成点与竞技场追踪敌人清除情况，判断何时完成关卡，并管理“解锁状态”的切换（玩家可通过传送门离开关卡）。

敌人生成机制请参见 [Enemy Spawn System](<敌人生成系统.md>)。竞技场波次机制请参见 [Arena Combat System](<竞技场战斗系统.md>)。传送门触发区域与 TMX 加载请参见 [TMX Loading and Collision](<TMX 加载与碰撞.md>)。

## 系统概览

关卡推进系统管理三种互斥状态：

1. **Active（进行中）** - 战斗尚未结束；传送门锁定
2. **Cleared（已清理）** - 所有目标完成；传送门解锁并播放特效
3. **Exiting（离开）** - 玩家与传送门交互返回地图

该系统集中在 `LevelMap` 中实现，并由 `GameScene` 进行编排；完成状态通过 `GameProgressSaveData::isLevelCleared` 持久化。

## 完成度追踪状态

### 状态变量

`LevelMap` 维护了三个计数/标记，它们共同决定关卡是否完成：

| 变量 | 类型 | 用途 |
| --- | --- | --- |
| `_currentActiveMonsters` | `int` | 存活怪物数量（生成时递增，死亡时递减） |
| `_pendingEnemySpawnPoints` | `size_t` | 尚未触发的 `enemy_g` 生成点数量 |
| `_isLevelCleared` | `bool` | 是否已触发“关卡清理完成” |

此外，`_arenas` 中的每个 `ArenaConfig` 会用 `isFinished` 表示该竞技场是否完成。

## 与自动存档的集成

关卡清理状态会通过自动存档系统被持续写入：

```mermaid
sequenceDiagram
  participant p1 as LevelMap
  participant p2 as GameScene
  participant p3 as SaveManager

  p1->>p1: triggerLevelClear()
  note over p1: _isLevelCleared = true
  loop Every 60 seconds
    p2->>p2: update(dt)
    p2->>p3: tickAutoSave(dt)
  alt Timer expired
    p3->>p2: Trigger auto-save
    p2->>p2: fillProgressDataForSave()
    p2->>p1: isLevelCleared()
    p1-->>p2: true
    p2->>p3: saveGame(slotIndex, player, progressData)
    p3->>p3: Serialize + write to localStorage
  end
  end
```

**自动存档集成说明**

由于 `isLevelCleared` 会被写入每一次 `GameProgressSaveData`，清理状态会被手动存档与 60 秒自动存档一并捕获。这保证玩家清理完关卡后可以安全退出而不丢进度。
