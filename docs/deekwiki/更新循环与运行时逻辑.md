## 目的与范围

本文解释 `GameScene` 的逐帧更新逻辑，包括按优先级划分的执行分支、子系统协作以及运行时状态管理。内容涵盖核心 `update()` 方法，并说明其如何与刷怪管理、自动存档与 UI 冻结机制集成。

关于进入更新循环前的初始化过程，请参阅 [初始化流水线](<初始化流程.md>)。关于运行时的物理碰撞处理，请参阅 [物理与战斗接触](<物理与战斗接触回调.md>)。

## 主更新循环入口

`GameScene::update()` 会在初始化期间通过 `scheduleUpdate()` 注册，并每帧执行一次。它采用“优先级分支结构”：死亡状态优先于暂停状态，暂停优先于正常玩法。

**update 方法结构**

```mermaid
flowchart TD

Entry["GameScene::update(dt)"]
CheckDeath["玩家死亡？"]
CheckDeathUI["死亡菜单<br>是否已显示？"]
ShowDeathMenu["显示死亡菜单<br>_uiController->showDeathMenu()"]
UpdateUIOnly["仅更新 UI<br>_uiController->update(dt)"]
ReturnEarly["return"]
CheckPause["游戏暂停？<br>_isPaused"]
UpdateUIAndSave["更新 UI<br>处理存档请求"]
FullUpdate["完整更新：<br>- 输入控制器<br>- UI 控制器<br>- Boss 生命周期<br>- 刷怪更新<br>- 竞技场更新<br>- 存档请求"]

Entry -.-> CheckDeath
CheckDeath -.->|"Yes"| CheckDeathUI
CheckDeathUI -.->|"No"| ShowDeathMenu

UpdateUIOnly -.-> ReturnEarly
CheckDeath -.->|"No"| CheckPause
CheckPause -.->|"Yes"| UpdateUIAndSave
UpdateUIAndSave -.-> ReturnEarly
CheckPause -.->|"No"| FullUpdate
FullUpdate -.-> ReturnEarly
```

## 优先级层级 1：死亡状态处理

当玩家死亡（`_player->isDead()` 返回 true）时，更新循环会冻结所有玩法系统，只更新 UI 层。这保证死亡菜单可交互，同时防止物理模拟与敌人 AI 继续推进玩法状态。

**死亡状态执行路径**

| 条件 | 行为 | 仍在运行的系统 |
| --- | --- | --- |
| `_player->isDead() && !_uiController->isDeathMenuShowing()` | 仅首次显示死亡菜单 | 仅 UI |
| `_player->isDead() && _uiController->isDeathMenuShowing()` | 仅更新 UI | 仅 UI |

死亡菜单（由 `GameUIController` 管理）提供“重开关卡”或“返回地图”的选项。死亡状态下物理世界仍会继续模拟（物理体可能还有速度），但不会再执行新的玩法逻辑。

**实现细节**

```mermaid
sequenceDiagram
  participant GS as GameScene::update(dt)
  participant PC as PlayerCharacter
  participant UI as GameUIController
  participant DM as PlayerDeathMenu
  participant LM as LevelMap
  participant SM as SaveManager

  alt 玩家已死亡
    GS->>PC: isDead()?
    PC-->>GS: true
    GS->>UI: isDeathMenuShowing()?
    UI-->>GS: false/true
    opt 首次进入死亡状态
      GS->>UI: showDeathMenu()
      UI->>DM: create and display
    end
    GS->>UI: update(dt)（仅 UI）
  else 正常状态
    GS->>PC: update(dt)
    GS->>UI: update(dt)
    GS->>LM: updateEnemySpawns(...)
    GS->>LM: updateArenas(...)
    GS->>GS: processSaveRequests(dt)
    alt 有即时存档请求
      GS->>SM: consumeImmediateSaveRequest()
      GS->>GS: saveToActiveSlotInternal()
    else 自动存档计时到期
      GS->>SM: tickAutoSave(dt)
      GS->>GS: saveToActiveSlotInternal()
    end
  end
```

## 输入控制器更新

`GameInputController` 每帧处理键盘状态，用于更新玩家移动意图、技能冷却与落地状态。它不会直接移动玩家，而是设置状态标志，让 `PlayerCharacter` 读取并决定行为。

**输入更新职责**

| 组件 | 用途 | 更新频率 |
| --- | --- | --- |
| 移动意图（`moveLeft`/`moveRight`） | 由按键按下/释放设置，由 `PlayerCharacter` 的物理更新消费 | 每帧 |
| 落地状态（`isGrounded`） | 由物理接触回调更新，用于跳跃校验 | 每帧 |
| 动作锁（`isActionLocked`） | 防止同时攻击/施法；动画结束时清除 | 每帧 |
| 技能冷却 | 在 `SkillComponent` 中递减；输入控制器在使用前查询 | 每帧 |

输入控制器通过回调查询外部状态（例如 `setIsPausedGetter()`、`setGateQuery()`），而不是保存副本，从而保证与 `GameScene` 的权威状态一致。

 [GameInputController.h L1-L100](https://github.com/lilong555/Adventure-King/blob/60df0f40/GameInputController.h#L1-L100)

## UI 控制器更新

`GameUIController` 更新所有 HUD 元素并管理菜单生命周期。它独立于暂停状态运行，因此即使世界冻结，UI 动画与交互仍可正常进行。

**每帧 UI 更新任务**

```mermaid
flowchart TD

UIUpdate["GameUIController::update(dt)"]
StatusBar["PlayerStatusBar：<br>HP/MP/XP 条动画"]
SkillBar["SkillBar：<br>冷却进度圆环"]
BossBar["BossHealthBar：<br>HP + 破防条<br>(若 Boss 激活)"]
InteractionHint["交互提示：<br>传送门提示<br>NPC 提示"]
MenuTransitions["菜单过渡：<br>淡入淡出<br>滑动动画"]

UIUpdate -.-> StatusBar
UIUpdate -.-> SkillBar
UIUpdate -.-> BossBar
UIUpdate -.-> InteractionHint
UIUpdate -.-> MenuTransitions
```

UI 控制器不会直接读取玩家状态；它通过初始化时注册的绑定/回调接收更新（例如 `PlayerStatusBar::bindPlayer()`、`SkillBar::bindPlayer()`）。这样可以让 UI 与玩法逻辑解耦，并在暂停期间保持动画。

## Boss 生命周期管理

更新循环每帧检查 Boss 是否死亡，并进行清理，避免内存泄漏与 UI 异常。此逻辑是对“单个 Boss 实体”的简化版本（硬编码），区别于普通怪物的通用生命周期管理。

**Boss 死亡清理**

```mermaid
sequenceDiagram
  participant p1 as update(dt)
  participant p2 as _boss
  participant p3 as GameUIController
  participant p4 as BossHealthBar

  p1->>p2: isDead()?
  p2-->>p1: true
  p1->>p3: getGameUI()
  p3-->>p1: GameUI*
  p1->>p3: unbindBoss()
  p3->>p4: Fade out and remove
  p1->>p1: _boss = nullptr
  note over p1: 清空 Boss 引用<br/>下一帧自动从场景移除
```

Boss 不会在死亡时自动移除（在 [GameScene.cpp L817](https://github.com/lilong555/Adventure-King/blob/60df0f40/GameScene.cpp#L817-L817)

 中设置 `setAutoRemoveOnDeath(false)`），因此必须显式解绑 UI 并清空引用。普通怪物则由 `LevelMap` 管理，并会自动移除。

**来源：** [GameScene.cpp L904-L914](https://github.com/lilong555/Adventure-King/blob/60df0f40/GameScene.cpp#L904-L914)

## 刷怪管理

敌人生成委托给 `LevelMap::updateEnemySpawns()`：它检查玩家与刷怪点的距离，并在触发时创建怪物。更新会被节流为每 0.2 秒执行一次（可通过 `ENEMY_SPAWN_CHECK_INTERVAL_SECONDS` 配置）以降低 CPU 开销。

**刷怪更新流程**

```mermaid
flowchart TD

UpdateSpawns["LevelMap::updateEnemySpawns()"]
Accumulator["累积 dt<br>_enemySpawnCheckAccumulator += dt"]
CheckThrottle["累积值 ≥<br>SPAWN_CHECK_INTERVAL？"]
ResetAccumulator["重置累积器<br>_enemySpawnCheckAccumulator = 0"]
IteratePoints["遍历 _enemySpawnPoints"]
CheckSpawned["hasSpawned?"]
CheckDistance["到玩家距离<br>≤ viewDistanceX?"]
SpawnMonster["通过 createMonsterByType()<br>创建怪物"]
SetTarget["monster->setTarget(player)"]
SetHome["monster->setHome(spawnPos)"]
AddToScene["gameLayer->addChild(monster)"]
MarkSpawned["spawnPoint.hasSpawned = true"]
Decrement["_pendingEnemySpawnPoints--"]
SkipUpdate["跳过（等待下一次检查）"]
NextPoint["继续下一个点"]

UpdateSpawns -.-> Accumulator
Accumulator -.-> CheckThrottle
CheckThrottle -.->|"No"| SkipUpdate
CheckThrottle -.->|"Yes"| ResetAccumulator
ResetAccumulator -.-> IteratePoints
IteratePoints -.->|"No"| CheckSpawned
CheckSpawned -.->|"Yes"| NextPoint
CheckSpawned -.->|"Yes"| CheckDistance
CheckDistance -.->|"No"| NextPoint
CheckDistance -.-> SpawnMonster
SpawnMonster -.-> SetTarget
SetTarget -.-> SetHome
SetHome -.-> AddToScene
AddToScene -.-> MarkSpawned
MarkSpawned -.-> Decrement
```

**刷怪点状态恢复**

读档时会通过 `LevelMap::applyEnemySpawnPointStates()` 恢复刷怪点状态以避免重复生成。`hasSpawned` 标志会随存档持久化，确保每个刷怪点在一次通关流程中只触发一次。

## 竞技场战斗管理

竞技场更新由 `LevelMap::updateArenas()` 处理：检查玩家是否进入竞技场触发区，并生成“波次”敌人。与普通刷怪点不同，竞技场可以连续生成多个波次，并在战斗期间锁门。

**竞技场更新顺序**

```mermaid
sequenceDiagram
  participant p1 as GameScene::update()
  participant p2 as LevelMap
  participant p3 as ArenaConfig*
  participant p4 as onArenaCameraRequest
  participant p5 as MonsterBase

  p1->>p2: updateArenas(player, gameLayer, createMonsterByType)
  loop For each arena in _arenas
    p2->>p3: Check if activated
  alt Not activated
    p2->>p3: Player in trigger rect?
  alt Yes
    p2->>p3: isActivated = true
    p2->>p4: onArenaCameraRequest(true, lockPos)
    note over p4: Lock camera to arena center<br/>Play gate close animation
    p2->>p2: spawnNextWave()
  end
  else Activated and not finished
    p2->>p3: Check wave completion
  alt Current wave cleared
    p2->>p2: currentWaveIndex++
  alt More waves remaining
    p2->>p2: spawnNextWave()
  else All waves done
  else All waves done
  else All waves done
    p2->>p3: isFinished = true
    p2->>p4: onArenaCameraRequest(false, Vec2::ZERO)
    note over p4: Unlock camera<br/>Open gates
    p2->>p2: checkAllClear()<br/>(may trigger level completion)
  end
  end
  end
  end
```

**竞技场怪物追踪**

每只竞技场怪物会以 `"arena:<arenaID>"` 形式命名（例如 `"arena:arena_01"`），用于与其父竞技场关联。怪物死亡时，`onMonsterKilled()` 回调会减少竞技场的 `activeMonstersCount`，并检查当前波次是否完成。

**来源：** [GameScene.cpp L927-L931](https://github.com/lilong555/Adventure-King/blob/60df0f40/GameScene.cpp#L927-L931)

 [LevelMap.cpp L647-L828](https://github.com/lilong555/Adventure-King/blob/60df0f40/LevelMap.cpp#L647-L828)

## 自动存档集成

更新循环通过 `processSaveRequests()` 处理存档请求，它同时处理“即时存档”（由升级、换装等状态变化触发）与“定时自动存档”（默认每 60 秒一次）。

**存档请求处理流程**

```mermaid
flowchart TD

ProcessSaves["processSaveRequests(dt)"]
CheckManager["SaveManager<br>exists?"]
CheckSlot["已分配活动存档槽？"]
CheckImmediate["consumeImmediateSaveRequest(reason)?"]
SaveImmediate["saveToActiveSlotInternal()<br>Toast: '自动保存（reason）'"]
TickAutoSave["tickAutoSave(dt)?"]
SaveAuto["saveToActiveSlotInternal()<br>Toast: '自动保存'"]
Return["return"]

ProcessSaves -.-> CheckManager
CheckManager -.->|"No"| Return
CheckManager -.->|"Yes"| CheckSlot
CheckSlot -.->|"No"| Return
CheckSlot -.->|"Yes"| CheckImmediate
CheckImmediate -.->|"Yes"| SaveImmediate
SaveImmediate -.-> Return
CheckImmediate -.->|"No"| TickAutoSave
TickAutoSave -.->|"Yes"| SaveAuto
TickAutoSave -.->|"No"| Return
SaveAuto -.-> Return
```

**即时存档触发点**

当关键状态变化发生时，不同子系统会通过 `SaveManager::requestImmediateSave(reason)` 排队请求，并在下一帧 `processSaveRequests()` 里被消费。

| 触发事件 | reason 字符串 | 触发方 |
| --- | --- | --- |
| 玩家升级 | "升级" | `PlayerCharacter::addExperience()` |
| 装备变更 | "装备变更" | `InventoryComponent::equipItem()` |
| 学习技能 | "技能学习" | `SkillComponent::learnSkill()` |
| 分配属性 | "属性分配" | `AttributeComponent::allocateAttributePoint()` |

**自动存档计时器**

自动存档计时由 `SaveManager::tickAutoSave(dt)` 管理：累积 dt，在达到间隔（默认 60 秒）时返回 `true`。成功存档后会通过 `SaveManager::resetAutoSaveTimer()` 重置计时器，避免短时间内重复存档。

**来源：** [GameScene.cpp L975-L1011](https://github.com/lilong555/Adventure-King/blob/60df0f40/GameScene.cpp#L975-L1011)
